# ADR-0003: Иллюстрации асан — SVG-фигурки из координатных данных

- Статус: принято
- Дата: 2026-11-11

## Контекст

Для каждой асаны нужна иллюстрация. Варианты:

1. Фотографии / профессиональные иллюстрации — проблемы с авторскими правами,
   весом, единством стиля.
2. Внешние изображения по ссылкам — зависимость от доступности источников.
3. Собственные векторные схемы.

## Решение

Схематичные фигурки, заданные декларативно координатами в `src/data/poses.ts`
(сетка 100×100 на кадр). Рендер — `src/components/AsanaFigure.tsx`.

Модель фигуры (актуализировано 2026-11-12):

- `head` — голова (круг, заливка фоном темы);
- `torso` — залитый контур торса (плечи → таз);
- `arms` / `legs` — парные конечности как трёхточечные сегменты
  (плечо–локоть–кисть, бедро–колено–стопа); рисуется только средний сустав;
- кисть — открытый кружок, стопа — чёрточка поперёк голени;
- дальняя сторона (left) бледнее и под ближней (right);
- руки — цвет `--tg-link`, ноги — `--tg-text` (чтобы различать конечности);
- `drishti` — точка взгляда, линия от головы;
- `ground` — пунктирная линия пола.

Поза может состоять из нескольких кадров (`figures`): вход, удержание, выход;
для Сурья Намаскар — полная последовательность виньяс (11 и 19 кадров).
`mainFrame` задаёт основной кадр для превью в списке / шторки.
В **справочнике (шторка)** и **практике** для мультикадра — **общая схема виньяс**
(все фигуры сразу, с номерами), без покадровой навигации.
В практике — CSS-grid ячеек + таймер; длинная текстовая расшифровка Сурий скрыта.
Одиночные асаны и превью списка — `mainFrame` / thumbnail.

**Стоп-кран:** не возвращать покадровый UX и не менять модель «схема vs один кадр»
без явного подтверждения владельца.
Поза выбирается по ключу `pose` из данных асаны.

## Последствия

Плюсы:

- Нет растровых ассетов: иллюстрации — часть JS-бандла, ноль сетевых запросов.
- Нет проблем с лицензиями.
- Цвет берётся из текущей темы (currentColor-подход через CSS-классы) —
  автоматическая поддержка светлой/тёмной темы Telegram.
- Единый стиль всех поз.
- Мультикадровость — основа для будущего режима практики (TD-10).

Минусы (см. техдолг):

- Схемы всё ещё упрощены: сложные скрутки и захваты узнаваемы хуже (TD-1).
- Координаты подобраны вручную, нет валидации читаемости поз (TD-2).

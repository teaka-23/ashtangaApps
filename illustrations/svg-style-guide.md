# SVG Style Guide: иллюстрации асан (монохромный силуэт)

> Актуально на 2026-11-19. Источник истины — код, а не этот файл:
> `illustrations/figure.mjs` (анатомия), `illustrations/mono.mjs` (силуэт),
> `illustrations/build.mjs` (сборка), `illustrations/audit.mjs` (контроль).
> Если гайд и код разошлись — прав код, гайд обновляем.
>
> Прежняя версия гайда описывала строгий line-art (`fill="none"`,
> `currentColor`, `stroke-width="6"`, только `M`/`L`). В приложении этот стиль
> не используется: line-art-рендерер и его сэмплы удалены из репозитория,
> PNG-артефакты ревью не хранятся.

---

## 1. Конвейер

1. **Анатомия.** `poses-*.mjs` описывает асану хелперами `draw.*` из
   `figure.mjs` и заворачивает в `svgDocument(body)`: система 200×200, `y` вниз,
   лицо смотрит в `+x`, пол — `GROUND = 168`.
2. **Силуэт.** `toSilhouette(fn())` выбрасывает пол, тень, блики, пунктир
   взгляда и контурные линии без заливки, снимает `<g>`, все оставшиеся формы
   заливает одними чернилами с тонким швом того же цвета.
3. **Базлайн.** `snapToGround(...)` сдвигает все Y так, чтобы нижняя точка
   чернил встала на `y = 168` (пол в силуэт не попадает, иначе позы «висят»).
4. **Файл.** Результат пишется в `illustrations/<раздел>/<номер>-<имя>.svg`.

Команды: `npm run illustrations` — пересобрать все 108 SVG;
`npm run illustrations:audit` — текстовый контроль (см. §10).

Ручной просмотр для владельца — `illustrations/preview.html` (галерея всех
SVG по блокам, открывается в браузере; список кадров там правится вручную).

## 2. Формат готового SVG

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="-8 0 216 200"><path d="…" fill="#2b2320" stroke="#2b2320" stroke-width="1" stroke-linejoin="round"/>…</svg>
```

| Атрибут | Значение | Комментарий |
|---------|----------|-------------|
| `viewBox` | `-8 0 216 200` | `CANVAS` из `mono.mjs`: общий холст серии. Шире 200, потому что три позы (supta-konasana, setu-bandhasana, mayurasana) выходят за `0..200` на 2–6 px. Один холст = один масштаб. |
| элемент | `<path>` + один `<ellipse>` (голова) | `toSilhouette` сохраняет `<ellipse>`/`<circle>` источника, только перекрашивая их в чернила; `<line>` (пол) и обёртки `<g>` выкидываются. В текущей серии: 108 эллипсов (по одному на позу) и 0 `<circle>`. |
| `fill` / `stroke` | `#2b2320` (`INK`) | Тёплые чернила. Цвет задаётся один раз: SVG грузится через `<img>`, где `currentColor` не наследуется и разрешается в чёрный. |
| `stroke-width` | `1` (`SEAM`) | Тонкий шов того же цвета убирает светлые щели антиалиасинга между соседними заливками. |
| `stroke-linejoin` | `round` | Без шипов на стыках. |
| `fill-opacity` / `stroke-opacity` | `0.45` | Дальние конечности (в источнике цвета `#d7a888` / `#c9aa90`) — дымка глубины. |

Фрагмент реального файла (`seated1/25b-dandasana.svg`, первая фигура):

```xml
<path d="M 102.6,161.2 L 122.1,162.2 Q 123.7,162.3 125.3,162.3 L 154.3,162.2 Q 155.9,162.2 157.1,161.1 L 159.2,159.2 Q 160.4,158.1 159.3,157 L 157.3,154.9 Q 156.1,153.8 154.5,153.7 L 125.9,151.8 Q 124.3,151.7 122.7,151.5 L 103.7,148.9 Q 102.1,148.7 102,150.3 L 101.1,159.5 Q 101,161.1 102.6,161.2 Z" fill="#2b2320" stroke="#2b2320" stroke-width="1" stroke-linejoin="round"/>
```

В файле 11–15 таких путей. Голова — отдельный эллипс с теми же чернилами:

```xml
<ellipse cx="98" cy="46" rx="10.08" ry="11.2" fill="#2b2320" stroke="#2b2320" stroke-width="1" stroke-linejoin="round"/>
```

Целиком файл — 3.4–5.0 КБ.

## 3. Запрещено в готовом SVG

- `<g>`, `<defs>`, `<clipPath>`, `<mask>`, `<symbol>`, `<use>`;
- `<line>` и пол: линия земли в силуэт не входит;
- тени (`rgba(…)`), блики (`opacity="0.x"` на фигуре), пунктир взгляда
  (`#2481cc`), контурные линии без заливки (`fill="none"`);
- `currentColor`, `transform`, `style`, фильтры, градиенты, маски;
- любой текст, подписи, XML-комментарии;
- цвета кроме чернил `#2b2320` (и их прозрачности `0.45`);
- относительные команды путей (`l`, `q`, `c`, `a`) и `H`/`V` — только
  абсолютные (см. §6);
- единицы измерения (`px`, `%`) в координатах.

## 4. Геометрия и опорные величины

- **Базлайн:** нижняя точка чернил любой позы = `y = 168`. Это касается и
  инверсий: у Ширшасаны на полу макушка, поэтому `maxY` тоже 168.
- **Голова:** `draw.head` / `draw.headFront`, радиус по умолчанию `11.2`;
  в силуэте остаётся `<ellipse rx ≈ 0.94r, ry = r>` с теми же чернилами
  (`<circle>` в готовых файлах не используется).
- **Пропорции:** голова ≈ 1/7 фигуры; высота силуэта — от 28 единиц
  (Шавасана, лёжа) до 168 (Уттхита Триконасана), стоячая Самастхити ≈ 134
  (макушка ~34 → стопы 168), средняя по серии ≈ 104.
- **Симметрия:** фронтальные позы — относительно `x = 100`.
- **Кадрирование:** `frameToContent(svg, 18)` в `figure.mjs` умеет обрезать
  пустое поле, но в текущем конвейере не вызывается — `viewBox` всегда
  перезаписывается общим `CANVAS`, чтобы масштаб всех 108 поз совпадал.
- **Габарит:** после сборки фигура не должна выходить за холст; центр
  компактных поз — около `x = 100` (мягкие допуски см. §10).

## 5. Анатомия: только хелперы `figure.mjs`

`path` вручную не пишем: направление конечностей задаётся точками суставов,
а не «догадкой» рендера.

| Хелпер | Назначение |
|--------|------------|
| `draw.leg(hip, knee, ankle, opt)` | нога целиком (бедро + голень + стопа); `opt`: `far`, `foot` (`flat`/`tucked`/`tops`/`flex`/`free`/`lotus`), `toe` (+1 вправо), `underShorts` |
| `draw.thigh` / `draw.shin` | части ноги отдельно (когда бедро уходит под шорты или стопа в лотосе) |
| `draw.arm(shoulder, elbow, wrist, opt)` | рука; `opt`: `far`, `hand` (`hang`/`hold`/`palm`/`flat`/`prayer`/`toe`/`up`), `fingers` |
| `draw.torso(points, opt)` | корпус одним гладким контуром; `opt.arch` — мягкая дуга прогиба |
| `draw.shorts(points)` / `draw.shortsFrame` | шорты; `svgDocument` поднимает их верхним слоем, чтобы всегда были поверх бёдер |
| `draw.head` / `draw.headFront` | голова в профиль / на зрителя |
| `draw.shadow(cx, rx)` / `draw.groundLine()` | тень и пол для исходника; **в силуэт не попадут**, на позу не влияют |
| `draw.smoothClosed(points)` | гладкий замкнутый контур на C-кривых; в текущих позах не используется (корпус идёт через `polySmooth` на Q) |

Правила: дальняя конечность помечается `far: true` (в силуэте станет дымкой),
а не порядком отрисовки; `underShorts: true` — бедро уходит под шорты.

## 6. Команды путей и координаты

Допустимы только **абсолютные** команды: `M`, `L`, `Q`, `A`, `Z` (и `C`, если
контур собран через `draw.smoothClosed`). Хелперы дают: капсулы — `M/L/A/Z`,
стопы и ладони — `M/L/Q`, корпус — `M/Q`. В готовых 108 файлах `C`
не встречается: 11–15 путей на позу, только `M/L/Q/A/Z`.

Относительные (`l`, `q`, `c`, `a`) и `H`/`V` запрещены: `snapToGround`
сдвигает Y, разбирая пары координат на месте, — на относительных командах
сдвиг был бы неверным.

Числа в исходнике округляются до 0.1 (`n()` в `figure.mjs`), после сдвига —
до 0.01. Экспоненциальная запись (`1e-7`) в готовых файлах не встречается.

## 7. Ракурсы

| Ракурс | Правило |
|--------|---------|
| Профиль (`side`) | по умолчанию: лицо в `+x`, грудь справа, ягодицы слева, носки вправо |
| Фронтальный (`front`) | симметрия относительно `x = 100`; стопы параллельны оси X |
| Лёжа на спине (`supine`) | голова вверху, стопы на `168` |
| Лёжа на животе (`prone`) | голова вбок, корпус вытянут по горизонтали |
| Инверсии (`inversion`) | ориентир — вертикаль `x = 100`; в силуэте нижняя точка (макушка или плечи) всё равно встаёт на `168` |

Позы одного блока рисуются в одном ракурсе; исключения — скрутки (профиль)
и стойки (инверсия).

---

## 8. Варианты A / B / C / D и дополнительные кадры

- Варианты асаны имеют **одинаковый базовый силуэт**: меняется только фрагмент
  из описания (положение рук/ног, глубина складки). Корпус, голова, таз
  не трогаются.
- Один кадр = один файл: `26-paschimattanasana-a.svg` … `29-paschimattanasana-d.svg`.
- Дополнительный кадр внутри той же асаны получает буквенный суффикс:
  `23b-utthita-hasta-padangusthasana-b`, `23c-…-c`, `25b-dandasana`.
- Несколько кадров в приложении — массив в `CARTOONS['<pose>']`
  (`src/data/cartoons.ts`): например
  `navasana: [svg('seated1/40-navasana-a'), svg('seated1/41-navasana-b')]`,
  `'utthita-hasta': [A, B, C]`.

## 9. Как добавить асану или кадр

1. Функция в `illustrations/poses-*.mjs` + строка в `FILES` этого модуля:
   `['29-paschimattanasana-d', paschimattanasanaD]`.
2. `npm run illustrations` → `npm run illustrations:audit` (нужно 0 ERR).
3. Приложение:
   - `src/data/cartoons.ts` — `CARTOONS[pose]` (путь к SVG);
   - новая асана дополнительно: `src/data/poses.ts` (fallback-рендер
     `AsanaFigure`, тест `series.test.ts` требует позу для каждой асаны),
     `src/data/primarySeries.ts` / `src/data/intermediateSeries.ts`,
     `src/i18n/content.ts` (`ENGLISH_NAME`, `NOTE_EN`).
4. Тесты: `npx vitest run` (`cartoons.test.ts` — кадры, `series.test.ts` —
   порядок и наличие позы).
5. Отметить в `docs/illustration-review.md`; расхождения с описанием —
   в `docs/illustration-mismatch-report.md`.

## 10. Контроль качества

`npm run illustrations:audit` — текстовый отчёт по геометрии, без рендера
картинок. PNG-превью не открывать: у модели нет image input (см. `.clinerules`).

| Проверка | Порог | Уровень |
|----------|-------|---------|
| клип холста | выход за `x ∈ [-8, 208]` / `y ∈ [0, 200]` больше 0.5 | ERR |
| базлайн | `maxY` отличается от 168 больше чем на 1.5 | ERR |
| мелкая фигура | максимальный габарит меньше 90 | WARN |
| сдвиг по X | ширина < 120 и центр вне `75..125` | WARN |
| дымка | нет ни одной формы с `opacity="0.45"` | WARN |
| точки | подпуть меньше 0.6 × 0.6 | WARN |
| волоски | подпуть уже 1.2 при длине больше 8 | WARN |

Состояние на 2026-11-19: 108 SVG, **0 ERR**, 15 WARN, все информационные:
8 «сдвигов по X» — глубокие складки и скрутки, где центр фигуры уходит от
`x = 100` (Пашчимоттанасана A–D, Джану Ширшасана B, Убхая
Падангуштхасана, Паригхасана, Мукта Хаста Ширшасана B), и 7 «мелких
фигур» — компактные позы с габаритом меньше 90 (Джану Ширшасана C,
Маричьясана B, Пиндасана, Баддха Падмасана, Лагху Ваджрасана, Гомукхасана B;
у Пашчимоттанасаны A срабатывают оба флага). Глазную оценку делает владелец.
Сборка идемпотентна: повторный `npm run illustrations` даёт те же файлы
(md5 совпадает).

## 11. Системный промпт для модели (вставить один раз)

> Ты — иллюстратор асан для мини-аппа. Рисуешь монохромный силуэт.
>
> - Анатомию собираешь в `illustrations/poses-*.mjs` хелперами `draw.*` из
>   `figure.mjs`; `path` вручную не пишешь.
> - Система 200×200, `y` вниз, пол `GROUND = 168`, лицо в `+x`; дальняя
>   конечность — `far: true`.
> - Сборка — `npm run illustrations` (внутри `toSilhouette` + `snapToGround`),
>   проверка — `npm run illustrations:audit`, нужно 0 ERR.
> - Готовый SVG: `<path>` + один `<ellipse>` головы, `fill`/`stroke` = `#2b2320`,
>   `stroke-width="1"`, `stroke-linejoin="round"`, дальние формы —
>   `fill-opacity`/`stroke-opacity` = `0.45`, `viewBox="-8 0 216 200"`.
> - Запрещено: `<g>`, `<line>`, тени, блики, `currentColor`, `transform`,
>   относительные команды путей, текст.
> - PNG/скриншоты не читать и не запрашивать: качество контролируется
>   геометрией и `audit`.
> - В ответе — только изменённые файлы и результат `audit`/тестов.
